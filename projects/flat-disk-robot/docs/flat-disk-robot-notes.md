# Flat Disk Robot Notes

These notes capture the first flat disk robot layout generated from the
refactored build process.

## Build Chain

The robot is generated by `projects/flat-disk-robot/flat_disk_robot/robot.py`
and exported through `synthcad.build`.

## Coordinate System

- Units are millimeters.
- The chassis disk is centered on the XY plane.
- Z is vertical.
- Forward is +Y.
- The drive axle is parallel to X.
- Wheel centers are at `x = +/-88 mm`, `y = -18 mm`, `z = 22 mm`.

The original target was 8 inches (`203.2 mm`). The current chassis is `216 mm`
diameter to leave enough room for the widened wheel pockets, perimeter wall,
and rear-mounted magnetic encoder boards.

## Included Parts

- Printable 216 mm disk chassis.
- Two imported Repeat Compact 1806 gearmotor references.
- Two generated `53 mm` diameter TPU D-bore wheels.
- Two imported AS5600 encoder module references.
- Two modeled 3 mm radius encoder magnets behind the motors.
- Imported Seeed Studio XIAO ESP32-S3 Sense controller reference.
- Imported OV2640 21 mm 160 degree camera reference.
- Generated TOF sensor board.
- Generated assumed radar module.
- Generated 4S LiPo reference pack.
- Perimeter wall with widened front sensor and rear service openings.
- Battery tray rails, strap slots, and M2 electronics standoffs.
- Central M2 electronics bay beside the battery for a small controller, ESC,
  power board, or adapter plate.
- Front vertical electronics bulkhead with TOF screw bosses and adhesive
  landings for the ESP32 camera board and radar module.
- Rear AS5600 mount plates behind the motors, extended down into the chassis
  base instead of carried by small center tabs.
- Front-edge OV2640 press-in camera mount with a circular lens socket and
  rear square body register.
- Narrow lid roof wheel wells over the side openings so the larger wheels clear
  the lid without changing the 216 mm circular plan envelope.
- Raised central service lid fastened with six M4 screws into printed insert bosses.
- Rounded capsule-style lid roof with a matching rounded front canopy over the sensor bay.
- Eight-hole circular vent pattern in the lid roof to promote passive airflow over the central electronics bay.
- Forward-offset rectangular lid cutout sized for a nominal `22 x 27 mm` press-fit switch.
- Shallow recessed rear-center lid logo reading `Designed by GPT-5.4 xhigh with build123d`
  as a larger, left-aligned single-line text block.
- Four per-side motor-screw service tunnels in the lower chassis so a slim driver can reach the face-mount screws.

## Battery Assumptions

`projects/flat-disk-robot/real-parts/battery.png` identifies an OVONIC 4S1P 14.8 V, 1550 mAh, 100C
pack. The visible dimensions are 2.87 x 1.42 x 1.50 inches, modeled as a
`73 x 36 x 38 mm` pack.

The generated battery model also includes lead clearance geometry, so its
overall exported bounding box is longer than the physical pack body.

## Sensor Placement

- The forward camera is now the imported `OV2640_21mm-160_camera.STEP`
  reference, centered on the front chassis edge.
- The ESP32 is rotated so the assumed USB edge points downward.
- A rectangular cutout is placed under the ESP32 for USB access.
- The OV2640 mount front face sits within `1 mm` of the `216 mm` disk edge.
  The lens socket uses the STEP-derived `5.5 mm` lens radius plus `0.15 mm`
  print tolerance, and the rear square register uses the `4.25 mm` half-size
  camera body plus the same tolerance.
- The TOF board and radar board are rotated vertically so their sensing sides
  face forward.
- The TOF board is flipped 180 degrees in its own vertical plane from the
  first robot layout. The screw bosses are mirrored with the same transform so
  they still line up with the board holes.
- The ESP32 and radar module use adhesive pads instead of screw holes.
- The TOF board uses screw bosses aligned to the six extracted mounting holes:
  `(-17.5, 10.25)`, `(-17.5, -4.75)`, `(17.5, 10.25)`,
  `(17.5, -4.75)`, `(-7.5, -10.25)`, and `(7.5, -10.25)`.
- The TOF board is now held `3 mm` farther forward so the connector has extra
  room at the bulkhead, and the boss pilot holes use the board's `3.1 mm`
  mounting-hole diameter instead of heat-set insert pockets.

The radar module is an assumed placeholder because no radar STEP or drawing was
present in `projects/flat-disk-robot/real-parts/`.

## Lid And Fastener Assumptions

The new lid is a raised circular cover sized to protect the battery and middle
controller bay while matching the 216 mm chassis disk in plan view. The roof is
now a full circular top plate, with wall openings left at the front, rear, and
wheel-side regions so the lower chassis layout and sensor access stay usable.
The perimeter skirt now drops to the top of the chassis wall so the upper and
lower shells visually meet around the sides instead of leaving a gap.

Fastener stack assumptions encoded in
`projects/flat-disk-robot/flat_disk_robot/robot.py`:

- Six lid mount points: `(-58, -78)`, `(58, -78)`, `(-82, 24)`, `(82, 24)`,
  `(-68, 60)`, and `(68, 60)`.
- Printed lid through-holes use `4.25 mm` M4 clearance all the way through the
  roof/pad stack so standard M4 screw heads are captured on the top surface of
  the lid instead of dropping through the cover.
- Chassis bosses use assumed `5.6 mm x 8.0 mm` M4 heat-set insert pockets.
  These will look much larger than an M4 through-hole because they are sized to
  the insert outer diameter, not to the screw shank.
- The lid roof now adds a centered-forward switch cutout for a nominal
  `22 x 27 mm` panel body with `0.15 mm` press-fit relief per side; its center
  is at `(0, 52)` so the opening stays forward of the modeled battery envelope.
- The front perimeter-wall sensor opening keeps the `144 mm` nominal rectangular
  slot, but the cut now carries farther around the circular chassis shoulders to
  add `25.4 mm` of effective side clearance on both the left and right sides of
  the front sensor bay. The lid skirt mirrors that deeper front cut while the
  rear service opening remains shallow.
- The circular roof now uses the full `216 mm` chassis diameter as its outer
  planform, so the robot reads as a matched top/bottom disk in review renders
  and the PR diff viewer.
- A `8 x Ø8 mm` circular vent pattern was added near the roof center so heat
  can escape from the battery/controller bay and so high-fidelity PR viewers
  can show whether repeated round features stay smooth in the exported mesh.
- A `0.35 mm` deep engraved text logo is centered at `(0, -50)` on the rear
  half of the top roof as a left-aligned single-line block at `8.0 mm` text size,
  so it stays clear of the switch cutout, vent ring, and lid fasteners while
  preserving the flat outside top face.
- Front and rear wall openings still align with the chassis sensor and service
  cutouts, while the large side wall openings stay around the wheel/motor zones
  so the lower chassis package remains unchanged.
- The individual lid pads were trimmed slightly so the rear screw pads stay
  inside the circular disk envelope instead of poking past the chassis radius,
  and now extend up to the roof underside so the screw holes are supported by
  full-height internal standoffs instead of isolated lower pads.
- The default reference assembly omits separate ghost driver keep-out solids so
  routine review renders stay readable.
- The adhesive landing projection for the ESP32/radar bulkhead was reduced from
  `8 mm` to `7 mm` to remove a small reference-board overlap found during
  assembly interference checking.
- The lower chassis now adds `8 x Ø7 mm` horizontal driver tunnels aligned to
  the motor face-mount screw pattern, matching the wheel hub screw-access hole
  so a driver has the same clearance all the way to the screw heads.
- The drive wheels grew by `6 mm` diameter, from `47 mm` to `53 mm`, while the
  motor axle stayed at `z = 22 mm`. The chassis wheel slots now grow with the
  wheel size and are `22 x 66 mm`, preserving the previous side clearance.
- The lid side wall openings remain broad service openings, and separate
  `24 x 58 mm` roof reliefs are cut directly above the wheels so the taller
  tires clear the lid top without trimming the outer disk edge.

Print intent for the lid:

- Material: PETG, ASA, or another tougher enclosure plastic rather than PLA.
- Orientation: print upside down with the outer top on the bed and the open
  side upward.
- Hardware: six top-entry M4 socket-head screws plus six heat-set inserts in
  the chassis bosses.
- Coupon recommendation: print one boss/pad pair first to tune insert hole size
  and top-hole fit before printing the full lid.

## Encoder Placement

The AS5600 modules are magnetic encoders. They are now mounted behind the
motors on the inboard side of each motor body, not near the wheels. Each motor
has a modeled small magnet reference on the rear shaft axis between the motor
and the AS5600 sensing face.

Current placement leaves about `2 mm` between the modeled magnet and the
AS5600 board face. This is a geometry placeholder until the actual magnet
thickness, glue stack, and AS5600 air-gap requirement are measured.

Each encoder now has a vertical mounting plate that extends down into the
chassis base across the full `30 mm` board width, removing the earlier small
center support tab. The plate hole pattern is aligned to the AS5600 STEP
mounting holes at `(+/-8.0, +/-8.0)` with `1.775 mm` source radii and printed
clearance added in the chassis.

## URDF Notes

The flat disk robot now has a first-pass complete URDF package generated by
`projects/flat-disk-robot/flat_disk_robot/urdf.py` and exported through
`synthcad.urdf_cli`.

Current URDF structure:

- Root link: `base_footprint`.
- Main body link: `base_link` for the printed chassis.
- Continuous joints: `left_wheel_joint` and `right_wheel_joint`.
- Fixed links: lid, battery, motors, encoder boards, encoder magnets, ESP32,
  OV2640 camera, TOF board, and radar module.
- Meshes are exported as STL in millimeters and referenced from URDF with a
  `0.001` scale so the robot loads in meters.

First-pass URDF mass assumptions encoded in
`projects/flat-disk-robot/flat_disk_robot/urdf.py`:

- Chassis: `0.230 kg`
- Lid: `0.075 kg`
- Battery: `0.180 kg`
- Each motor: `0.090 kg`
- Each wheel: `0.032 kg`
- Each AS5600 board: `0.006 kg`
- Each encoder magnet: `0.001 kg`
- ESP32-S3 Sense: `0.008 kg`
- OV2640 camera: `0.004 kg`
- TOF board: `0.006 kg`
- Radar placeholder: `0.004 kg`

These values are intended as usable starting assumptions for visualization,
TF trees, and basic simulation setup. They should be replaced with measured
hardware masses before any dynamics-sensitive work.

## Validation

Validated with:

```bash
uv run python -m compileall -f main.py synthcad projects
uv run python - <<'PY'
import sys, types
sys.modules['readline'] = types.ModuleType('readline')
import pytest
raise SystemExit(pytest.main(['-q']))
PY
uv run synthcad-build --project flat-disk-robot
uv run synthcad-inspect --target flat-disk-robot --interference all --view isometric --view rear-isometric
uv run synthcad-inspect --target flat-disk-robot-chassis --view isometric --view rear-isometric
uv run synthcad-inspect --target flat-disk-robot-lid --view isometric --view rear-isometric
uv run show-interference --target flat-disk-robot --view isometric --view rear-isometric
uv run synthcad-report --target flat-disk-robot-chassis --target flat-disk-robot-lid --target flat-disk-robot
uv run python -m synthcad.urdf_cli --target flat-disk-robot
```

The full robot assembly now inspects cleanly against the new lid geometry. The
only remaining reported assembly overlaps are the already-documented
intentional motor/wheel TPU press-fit interfaces. The direct `uv run pytest`
entry point currently segfaults before collection in this local uv Python while
importing `readline`, so the validated test run preloads a dummy `readline`
module before calling `pytest.main`.

Measured generated extents:

- Chassis STEP: `216.0 x 216.0 x 43.65 mm`.
- Lid STEP: `216.0 x 216.0 x 26.5 mm`.
- Robot assembly STEP: `216.0 x 216.0 x 57.0 mm`.
- Battery reference STEP: `93.0 x 36.0 x 38.2 mm`, including lead clearance.
- OV2640 camera reference: `12.5 x 11.3 x 21.75 mm`.
